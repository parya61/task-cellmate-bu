# уязвимости браузерных агентов и CELLMATE

Практическое исследование indirect prompt injection против браузерного агента
(browser-use + bu-latest) на стенде GitLab + проверка защиты CELLMATE.

## Структура

```
├── README.md                  ← этот файл
├── docs/
│   ├── cellmate-review.md     ← разбор статьи CELLMATE
│   ├── work-log.md            ← ход работы (мои мысли и действия)
│   ├── attack-vector.md       ← путь к атаке, что не сработало, почему bu-latest
│   └── results.md             ← результаты: 2 атаки + блокировка CELLMATE
├── code/                      ← agent.py (запуск агента bu-latest)
├── screenshots/               ← скриншоты
└── videos/
    ├── success.mp4                    ← успешная атака (эксфильтрация ключа)
    ├── cellmate_block_add_token.mp4   ← CELLMATE блокирует создание токена (атака 1)
    └── cellmate_block_exfilter.mp4    ← CELLMATE блокирует эксфильтрацию (атака 2)
```

## Суть за 2 минуты

1. Прочитал статью CELLMATE — понял, почему защита на HTTP-уровне: у кликов
   нет смысла, у HTTP-запросов есть.
2. Собрал стенд: публичный репо (точка старта — issue), приватный репо с
   секретом (GIGACHAT_API_KEY), приёмник эксфильтрации на сервере, два
   GitLab-аккаунта (разработчик/атакующий).
3. Атаки на универсальные модели (gpt-5.6-luna, minimax-m3) — 4/4 отражены
   с разбором. Тоже результат: «базовой защиты в LLM» недостаточно.
4. На целевой модели bu-latest обе атаки из ТЗ успешны: агент сам нашёл
   приватный репо, прочитал .env, извлёк ключ и направился на сервер
   атакующего.
5. Развернул CELLMATE (MV2, Chrome 138) — включённая политика заблокировала
   атаки: создание токена — deny, переход на внешний домен —
   ERR_BLOCKED_BY_CLIENT.
6. Проанализировал обход: контент разрешённых действий CELLMATE не проверяет
   (вектор — вставить ключ в комментарий к issue, действие разрешено).

## Ключевые цифры

- Атак на универсальные модели: 4 (все отражены)
- Успешных атак на bu-latest: 2 (по ТЗ)
- Точки блокировки CELLMATE: 2 (доступ + эксфильтрация)
